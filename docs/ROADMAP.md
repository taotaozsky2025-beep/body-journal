# 多型号路线图

以下是后续方向，尚未实现的项目不代表当前能力。

## 优先级 1：先降低使用门槛

- 引导页完成区域、设备和成员选择，替代手工编辑本机配置。
- 图形化连接私人数据仓库；保留完全离线模式。
- Windows 打包与代码签名、可靠升级/退出、登录到期提示；不要把 GitHub 网页登录误写为已完成 Git 授权。
- 纯合成演示数据和截图，避免用真实身体数据宣传。

## 优先级 2：先统一数据，再增加连接器

- 明确内部模型：UTC 时间戳、显示时区、来源、设备匿名键、成员匿名键、单位、字段是否来自原始测量或计算。
- 记录身份逐步升级为“来源 + 设备 + 成员 + 精确时间戳”；迁移时保留现有 CSV，不直接改写用户历史。当前每个安装目录只针对一个选定设备，亚秒记录会报错而非静默截断。
- 先增加有格式校验的标准 CSV/JSON 导入，让其他品牌的导出文件也能进入看板。
- 保留缺失值；不能把体重推算出的值当作秤测得的体脂、肌肉或水分值。不同设备字段即使同名，也要校对单位和量纲。

## 优先级 3：适配器分层

建议契约：`discover_devices` → `list_profiles` → `fetch_history(cursor)` → `normalize` → 共用归档层。认证、云端读取、原始字段映射与图表解耦。

优先复用 SmartScaleConnect 已支持的生态，分别接入米家、Mi Fitness、Zepp Life；HD01-B 等非通用接口保留独立适配器。不要按“品牌”写一个万能解析器。现有 `hd01s_sync.py` 仍是一个已限定型号的适配器，不是尚未实现的插件框架。

## 优先级 4：验证与维护

- 每个适配器提供去标识的纯合成 fixture，覆盖分页、乱序、同一时间重复、不同成员同一时间、单位转换、空历史和字段缺失。
- 每次新增型号必须验证：重复同步不增长、云端删历史不删本地、两台电脑新增数据可并集、失败不覆盖旧记录、授权信息不进入导出。
- 发布兼容性矩阵和升级说明；云端接口变化时允许单独停用一个适配器。
- 蓝牙采集单独作为长期实验，不与云端同步混在一起；手机后台限制和硬件网关要求需有实测证据。

## 数据保护

公开代码与私人数据仓库始终分离。后续可研究同步前加密、WebDAV 或本地 NAS 后端，让不愿存健康数据到 GitHub 的使用者有选择。任何加密功能都需先解决密钥备份与恢复，不能只用“加密”标签代替恢复测试。
